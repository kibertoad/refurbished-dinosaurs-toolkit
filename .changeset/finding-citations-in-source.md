Each finding or experiment cited in the rebuild's source now fails, as the work protocol has code in `src/` cite only the rules, formats, screens and bugs it implements. A new `--rebuild-source <dirs>` option (default `src`, empty turns it off) names the directories; files that a `--code` directory holds under them are read, and `tests` and `tools` are left out. The message gives the lines and names the candidates the protocol moves the citation to: the rules, formats, screens and bugs that are not superseded and list the finding or experiment in their `evidence`, or for a superseded one those its `superseded_by` leads to, as in `src/Game.cs: line 3 cites FND-SCORE-001, a finding, and code in the rebuild's source cites only the rules, formats, screens and bugs it implements; RULE-SCORE-001 lists it in its evidence: move the citation to it where the code implements it and the comment does not cite it yet, and delete it otherwise`. Where none does, the message says so. A superseded finding or experiment cited there is reported by this check in place of `which is superseded; cite what replaced it`.

For an address in the rebuild's source that no cited entry records, the address check's message names the rules, formats, screens and bugs that record it or cite evidence that does, and where none does, says to leave the address out and treat code that needs it as a gap in the spec, in place of `cite the finding that records it, or record it in a new one`. Other code directories keep that message.

A repository that passed fails wherever its source cites a finding or experiment. Settle each citation as the work protocol's Implementation batches section says; the migration guide's "Findings and experiments cited in the rebuild's source fail" has the steps.
